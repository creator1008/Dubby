이 문서는 Dubby가 사용자와 운영자에게 제공하는 기능과 비즈니스 규칙을 정의한다. 런타임·배포 경계는 SAD-001, 스키마·파이프라인 단계와 프롬프트 전문은 후속 문서에서 다룬다.

Dubby 비즈니스 로직 및 기능 명세서DUBBY-FRS-001

1. 문서 개요

1.1 목적

이 문서는 Dubby 3.0.12의 제품 기능과 비즈니스 규칙을 인수인계 기준으로 고정한다. 사용자가 무엇을 할 수 있는지, 크레딧이 언제 차감되는지, 추출·자막·더빙·다운로드가 어떤 전제에서 동작하는지를 코드에 근거해 기술한다.

1.2 범위

  • 포함: 사용자·운영자 기능, 언어·크레딧·결제 UX, 프로젝트 수명주기, 추출/자막/더빙/립싱크, Voice Box, 다운로드 경로, 관리자 화면, 데모 모드, 화면 라우트, 사용자 대면 오류.
  • 제외: 테이블 DDL·마이그레이션 이력, STT/번역/TTS 프롬프트 전문, Caddy/CORS/터널·배포 토폴로지. 이들은 각각 「데이터베이스/파이프라인 설계서」, 「AI 에이전트 및 프롬프트 명세서」, 「시스템 아키텍처 정의서(SAD-001)」에서 다룬다.
  • 사실의 기준: 저장소 현재 코드(제품 버전 3.0.12, PIPELINE_VERSION 3.0). 코드에 없는 버튼·요금제·언어는 적지 않는다.

1.3 대상 독자

  • 인수받는 제품·프론트 작업자: 화면 흐름과 크레딧·다운로드 분기를 오해하지 않는다.
  • 백엔드·운영: 잡 종류, 차감 시점, 관리자 조정, 재추출 규칙을 안다.
  • 모바일 담당: 웹 Stripe와 네이티브 RevenueCat, 저장 경로가 갈라지는 지점을 본다.

2. 제품 개요와 핵심 가치

Dubby는 원본 영상을 올리고(또는 URL로 가져오고), 대본을 추출·수정한 뒤, 대상 언어로 더빙해 내려받는 제품이다. 핵심 가치는 「배경음을 유지한 채 말만 바꾸는 것」과 「추출된 자막을 사람이 검수한 뒤 더빙하는 것」이다.

2.1 사용자 여정

[랜딩 /] --로그인--> [/login] --세션--> [/app] 더빙 이력
                              |
                              +--> [/app/new] 새 더빙
                              |       1) 파일 또는 URL + 언어·목소리
                              |       2) 업로드/수집 → 추출(transcribe)
                              |       3) 자막 검수 (원본 / 번역)
                              |       4) 더빙(dub) → Before/After
                              |       5) 다운로드
                              +--> [/app/voice-settings] My Voice Box
                              +--> [/app/billing] 크레딧 충전
                              +--> [/admin] 관리자(권한 있는 계정만)

2.2 한 줄 규칙

  • 추출은 자막을 만든다. 더빙은 그 자막을 읽는다. 3.0.12의 잘못된 할당·STT 꼬리 누락은 추출을 다시 돌려야 고쳐진다. 더빙만 재실행하면 옛 자막을 유지한다.
  • 크레딧은 더빙·립싱크 잡을 걸 때 서버가 선차감한다. 추출(transcribe)은 차감하지 않는다.
  • 소유권은 JWT sub만 믿는다. 클라이언트가 보낸 user id는 쓰지 않는다.

2.3 제품·파이프라인 버전

프론트 package.json과 API api/app/__init__.py의 __version__은 3.0.12다. 프로젝트 생성 시 pipeline_version 기본값은 "3.0"이다. VERSION.md에 따르면 3.0은 Gemini 3.7 Flash 전문서 STT·구어 번역·타임스탬프/화자, ElevenLabs v3 TTS이고, 3.0.12는 잘못 할당된 자막을 재번역하고 덮이지 않은 오디오 꼬리를 다시 듣는다.

3.2 결제 플랫폼 분기

src/lib/mobile.ts의 billingPlatform()은 Capacitor 플랫폼이 ios 또는 android이면 revenuecat, 그 외(웹)는 stripe다. 네이티브 앱 판정(isNativeApp)도 이 분기를 따른다.

3.3 UI 로케일 (i18n)

화면 언어는 src/lib/i18n/dictionaries.ts의 ko / en / vi 세 가지다. LanguageSwitcher로 전환한다. 더빙 원어·대상어(18개)와는 별개다. Voice Library 설명은 ui_locale이 영어가 아니면 서버가 번역을 시도한다.

3.4 인증이 필요한 구간

/app/*와 /admin은 AuthBoundary로 감싼다. Supabase 세션이 없으면 「로그인이 필요합니다」와 로그인 링크만 보인다. 데모 모드에서 Supabase가 없으면 세션 없이 자식 화면을 연다. 실제 API 모드에서 Supabase env가 없으면 인증 설정 누락 메시지를 띄운다.

5. 회원가입·로그인·세션

5.1 클라이언트 (Supabase PKCE)

getSupabase()는 flowType: "pkce", persistSession, autoRefreshToken을 켠다. detectSessionInUrl은 false다. OAuth·이메일 확인은 /auth/callback/에서 exchangeCodeForSession(code)를 수행한다.

경로동작
이메일 로그인signInWithPassword. 실패 시 「Email 또는 비밀번호가 올바르지 않습니다」.
회원가입이름·이메일·비밀번호(8자 이상)·확인. 국가 선택. 확인 메일이 켜져 있으면 받은편지함 안내 후 로그인.
Google OAuth활성. redirectTo는 공개 사이트 URL + /auth/callback/ (localhost로 돌아가지 않음).
Facebook / KakaoUI에 있으나 disabled: true (준비 중).
국가KR / US / VN / JP / CN / OTHER. 세션스토리지 dubby-signup-country로 콜백에서 프로필에 반영.
로그아웃signOut 후 랜딩 /로 이동.

5.2 서버가 신뢰하는 것

API는 Authorization: Bearer <jwt>만 검증한다(api/app/auth.py). HS256(레거시 시크릿) 또는 JWKS(RS256/ES256). 필수 클레임은 exp, sub. 사용자 id는 항상 sub의 UUID다. 관리자 여부는 app_metadata.role == "admin" 또는 app_metadata.roles에 admin이 있을 때다. 비활성 계정은 401 「Account is deactivated」.

클라이언트를 믿지 않는다 프로젝트·업로드 키·크레딧·Voice Box는 모두 JWT 소유자로 한정한다. R2 키는 users/{user_id}/...이며 서명 전에 prefix를 재검증한다. 본문에 user id를 실어 보내도 서버는 쓰지 않는다.

5.3 가입 시 프로필

Supabase handle_new_user 트리거가 profiles를 만들고 크레딧 원장에 signup_grant를 넣는다. 콜백은 표시 이름·provider·국가·last_login_at을 갱신한다. 가입 안내 문구는 「가입 시 무료 크레딧 30분이 지급됩니다」.

6. 크레딧 비즈니스 규칙

크레딧은 더빙 분(minute)이다. 잔액은 credit_ledger의 delta_minutes 합이다. 사용자는 GET /v1/credits로 잔액과 최근 50건만 읽는다. 지급·차감은 서버만 쓴다.

6.1 원장 reason

reason부호언제
signup_grant+신규 유저 트리거. 마이그레이션 값은 30분. 설정 기본 signup_credit_minutes=30.
dub_job−dub 잡 enqueue와 같은 트랜잭션.
lipsync_job−lipsync 잡 enqueue와 같은 트랜잭션.
purchase+Stripe 또는 RevenueCat 웹훅이 매핑한 분.
admin_adjust±관리자 조정. 0 불가, 사유 2–300자.
refund+잡이 failed/cancelled이고 charged_minutes > 0일 때 finish_job_with_refund.

6.2 차감 공식

dub / lipsync만 차감한다. transcribe는 0분이다.

duration = project.duration_seconds   # 추출 후 측정값. 없으면 409
multiplier = dub_cogs_minutes_multiplier      # 기본 1.0
           | lipsync_cogs_minutes_multiplier  # 기본 2.0
charge_minutes = ceil(duration / 60 * multiplier)

길이를 모르면 409 「Project duration unknown; run transcribe first」. 잔액이 부족하면 402 「Need {charge} credit minutes, have {balance}」. 데모 모드도 ceil(duration/60)이며 최소 1분, 메시지 「크레딧이 부족합니다. 필요 N분, 잔액 M분」.

6.3 Stripe (웹)

항목코드 기본값
구독 Checkoutkind=subscription. 월 분 stripe_subscription_minutes 기본 60. invoice.paid에서 구독 price id가 맞을 때 지급.
크레딧 팩kind=credits. stripe_credit_pack_minutes 기본 30. checkout.session.completed + payment + credit_kind=credits.
성공/취소 URL/app/billing/?checkout=success / cancelled (로컬 기본은 localhost:3000).
미설정시크릿이 없으면 400 「Billing is not configured」.

가격표 금액·Price ID는 환경 변수다. 이 문서는 분(minute) 기본값만 적는다. 사용자 id는 Stripe metadata dubby_user_id 또는 customer 매핑으로만 찾는다.

6.4 RevenueCat (네이티브)

웹훅 Authorization은 설정된 헤더와 상수 시간 비교한다. 크레딧을 주는 이벤트는 INITIAL_PURCHASE, RENEWAL, NON_RENEWING_PURCHASE다. REFUND는 상태 revoke. 분은 REVENUECAT_PRODUCT_CREDIT_MINUTES(product_id=분)를 먼저 보고, 없으면 entitlement 매핑의 최댓값을 쓴다. App User ID가 Dubby UUID가 아니면 400. UI의 Starter/30분 팩 문구는 웹 폴백 카피이며, 네이티브는 Offering의 실제 패키지 제목·가격을 그대로 보여 준다.

6.5 관리자 조정

POST /v1/admin/users/{id}/credits. delta_minutes −100000..100000, 0 불가. 사유 필수. 응답에 새 잔액과 조정자 id. UI는 「0이 아닌 크레딧과 조정 사유」를 요구한다.

6.6 UI 표시

AppShell 크레딧 알약은 balance.toFixed(1) + 「분」. 더빙/립싱크/취소 후 credits-changed 이벤트로 갱신한다. 이력 화면은 GET /v1/credits의 entries다.

7.3 생성·수정·삭제

GET  /v1/projects/{id}     → 소유자 또는 관리자

삭제 확인 문구: Supabase 기록과 R2·로컬 관련 파일이 영구 삭제되며 복구할 수 없다. URL 수집은 POST .../source-from-url 후 클라이언트가 status가 uploaded(또는 failed)가 될 때까지 폴링한다. 터널/모바일에서 긴 동기 다운로드가 끊기는 것을 피하기 위함이다.

8. 원본 업로드·URL 수집

8.1 한도 (api/app/config.py + UI)

한도값사용자 메시지
길이max_source_duration_seconds = 1800 (30분)source_too_long: 최대 30분(1800초)까지 자막 추출
원본 바이트max_source_bytes = 500 MBsource_too_large / FileUploader 500MB
업로드 안전 상한max_upload_bytes = 4 GiB스토리지 캡. UI는 500MB에서 먼저 막음

FileUploader는 video/*, audio/*, 또는 확장자 mp4/mov/m4v/webm/m4a/mp3/wav/aac만 받는다. 힌트: 「갤러리 또는 파일 · MP4 권장 · 최대 30분 · 모바일은 짧은 클립 권장」.

8.2 파일 업로드 흐름

브라우저                API                         R2
  |-- POST /v1/uploads/multipart ------------------>|
  |<- upload_id, key, part_size, part_count --------|
  |  (project.status = uploading, source_key 기록)
  |-- POST .../parts --> presign --> PUT part ------>|
  |-- POST .../complete --------------------------->|
  |  (project.status = uploaded)

키는 서버가 users/{uid}/projects/{pid}/source/...로 만든다. 완료 실패 시 abort. ETag가 CORS에 안 보이면 업로드가 실패한다.

8.3 URL 수집

UI 힌트: YouTube · Facebook · TikTok 페이지 URL, 또는 직접 MP4/WebM (최대 30분 · 500MB). 서버는 yt-dlp(쿠키 옵션)와 TikTok item-detail 우회를 쓴다. 수집 파일을 R2에 올린 뒤 uploaded. 실패 시 failed + error 500자. 타임아웃(408) 시 「영상 가져오기 시간이 초과되었습니다」. 업로드 실패 시 방금 만든 프로젝트는 삭제한다(데모 제외).

8.4 추출 전 동의

음성 처리 권한 체크박스가 꺼져 있으면 추출/일괄 생성이 비활성이다.

9. 추출 (transcribe)

9.1 사용자가 보는 것

새 더빙(/app/new)에서 「1. 파일 업로드 및 자막 추출」또는 「1. 링크로 가져오기 및 자막 추출」. 성공 후 상태는 ready_for_edit, 세그먼트 목록과 (있으면) 보이스 제거 미리보기 URL이 생긴다. 진행 라벨은 job-labels.ts의 transcribe 단계(오디오 추출, STT, 문맥 보정, 통번역, 자막 구간 저장 등)다.

9.2 잡

POST /v1/projects/{id}/jobs body { "kind": "transcribe" }. 차감 0. 프로젝트당 queued/running 잡은 하나. 취소는 POST /v1/jobs/{id}/cancel → cancelled by user.

9.3 3.0.12 — 재추출이 필요한 이유

3.0.12 워커는 (1) 잘못 할당·미번역으로 보이는 자막 idx를 다시 번역하고(idxs_needing_retranslate), (2) 덮이지 않은 오디오 꼬리를 다시 STT한다(_fill_uncovered_asr_tail). 이미 DB에 들어간 옛 세그먼트는 코드 배포만으로 바뀌지 않는다.

  • 기존 프로젝트의 잘못된 자막을 고치려면 추출을 다시 돌린 뒤 더빙한다.
  • 더빙만 다시 돌리면 옛 자막을 그대로 TTS한다.

9.4 일괄 생성

「더빙 영상 일괄 생성」은 추출 → 더빙을 한 흐름으로 이어 간다. 검수 없이 끝까지 간다. 데모는 로컬 step12 + 로컬 TTS + 로컬 렌더. 실제 API는 transcribe 완료를 기다린 뒤 dub을 enqueue한다.

9.5 데모 추출

데모는 로컬 step12 서버로 추출하고 applyStep12로 세그먼트를 넣는다. 로컬 run id가 없으면 「파일을 다시 추출해 주세요」.

10. 자막 편집

10.1 화면

세그먼트마다 원본 텍스트와 번역 텍스트, 원본 구간 미리듣기, (더빙 후) 더빙 미리듣기·발화 속도·감정톤. 헤더: 원본 ({언어}) / 번역 ({언어}). 화자 id가 있으면 「화자 N」.

10.2 저장 (bulk update)

PUT /v1/projects/{id}/segments. 항목 1–500. 필드: target_text, source_text, end_ms, speak_speed(0.5–1.5), source_end_ms, emotion_tone. 저장 후 전체 목록을 다시 받는다. 번역이 바뀌면 해당 idx의 더빙 미리듣기를 무효화한다. speak_speed는 R2 매니페스트에도 반영한다.

10.3 다시번역

원본을 고친 뒤 「다시번역」. 서버는 수정된 source를 문맥 보정하고 전문서 번역·정렬한 뒤 target을 갈아끼운다. 원본 수정이 없으면 「원본 텍스트 수정내역이 없습니다」. OpenAI 키가 없으면 400. 「번역보기」모달은 원본·번역 쌍을 한눈에 보여 준다.

10.4 발화 속도

에디터 speak_speed 0.5–1.5(0.05 스텝). 원본 구간(source_end_ms)은 속도가 바꾸지 않는다. 번역 슬롯 end_ms가 늘어나거나 줄어든다. 1.2×면 슬롯이 약 20% 짧다. 리셋은 항상 1.0(자연 속도).

10.5 출력 자막 모드

none / 원어 자막 / 더빙어 자막. 새 더빙과 에디터에서 바꿀 수 있다. Before/After 플레이어가 같은 모드로 자막을 겹친다.

11. 더빙 (dub)

11.1 시작 조건

  • 세그먼트가 있고 상태가 ready_for_edit, completed, 또는 failed(재시도).
  • 활성 잡이 없어야 한다.
  • voice_box면 My Voice Box에서 화자 수만큼 목소리를 고른다. 비어 있으면 「목소리 설정에서 추가」.
  • auto_clone이면 영상 화자를 IVC한다. Box 선택은 필요 없다.
  • 에디터에서 더빙 시작 전 자막을 저장한다.

11.2 목소리

모드동작
voice_box화자 1…N에 ElevenLabs voice id. 단일 화자 1슬롯, 다중은 최소 2.
auto_clone화자 음성으로 Instant Voice Clone 후 TTS.

전역 ELEVENLABS_VOICE_ID가 있으면 IVC를 건너뛰고 그 목소리만 쓴다(운영 설정). 목소리 없으면 voice_missing.

11.3 믹스·템포 (제품 수준, 프롬프트 아님)

설정기본제품 의미
mix_no_vocals_in_mask0.8Demucs 반주 스템을 더빙 말 아래에 선형 게인. 0.15는 BGM이 거의 안 들림. 0.8은 말 아래 음악이 분명히 남음.
tts_max_speedup1.5슬롯에 맞추는 최대 배속.
tts_min_tempo0.85너무 느린 늘리기를 제한. 압축·슬롯 연장을 우선.
tts_atempo_max1.5ffmpeg atempo 고품질 구간. 밖은 Rubber Band 선호.
voice_changer_after_ttsfalse켜면 TTS 후 STS(추가 비용).

품질 경고(quality_warnings)는 슬롯 맞춤 참고다. 실패가 아니며 결과 영상은 생성된다. asr_tail_* 경고는 꼬리 STT 재시도 결과다.

11.4 감정톤

프로젝트 기본 톤은 감지 실패 시 폴백. 구간별로 원본 목소리에서 감지하거나 에디터가 덮어쓴다. 허용: sad, angry, whisper, excited, energetic, calm, cheerful.

11.5 미리보기 재합성

POST .../segments/refresh-preview가 고친 번역에 대해 TTS 클립만 다시 만든다. 전체 mux가 아니다.

12. 립싱크

  • 선택 기능. 설정 lipsync_provider 기본 disabled.
  • disabled면 503 feature_unavailable: lip sync is not configured.
  • 더빙 출력(output_key)이 있어야 한다. 없으면 409 「Complete dubbing before premium lip sync」.
  • 차감은 ceil(duration/60 × lipsync_cogs_minutes_multiplier), 기본 배수 2.0.
  • 완료 시 다운로드는 lipsync_output_key를 output_key보다 우선한다.
  • 이력 에디터의 「프리미엄 립싱크」는 실제 API·status=completed·활성 잡 없음일 때만 활성. 데모는 비활성(「립싱크는 데모 모드에서 지원하지 않습니다」).

13. 보이스 박스 · 라이브러리 · My Voice

화면: /app/voice-settings. 「목소리를 복제하거나 Voice Library에서 골라 My Voice Box에 저장」.

13.1 Voice Library

GET /v1/voices/library. 페이지·언어·억양·카테고리·성별·연령·검색. ElevenLabs 공유 목소리를 가져온다. Category 열은 use_case를 우선한다. 미리듣기 URL이 있으면 재생.

13.2 My Voice Box에 추가

별명 필수, 최대 30자. 공유 목소리를 계정에 복사한 뒤 DB에 넣는다. 중복 별명/이미 추가된 목소리는 409 「Already in Voice Box, or nickname is taken」. 삭제 시 행 제거. IVC 행은 ElevenLabs voice와 R2 미리듣기도 지운다.

15. 결제 UX

15.1 웹 (Stripe)

/app/billing. 잔여 분 표시. 「Starter (구독)」→ checkout subscription → window.location.assign(url). 「30분 크레딧 팩」→ checkout credits. 데모는 「데모 모드에서는 결제가 비활성화되어 있습니다」.

15.2 네이티브 (RevenueCat)

공개 SDK 키: iOS NEXT_PUBLIC_REVENUECAT_IOS_API_KEY, Android ..._ANDROID_.... Purchases.configure의 appUserID는 Supabase user UUID. Offering 패키지를 나열하고 스토어 가격으로 구매. 복원·구독 관리 URL. 완료 메시지: 「크레딧은 스토어 확인 후 반영됩니다」(웹훅 후 원장 반영).

15.3 가격을 코드에 적지 않는 이유

Stripe Price ID와 RevenueCat product=minutes 매핑은 환경 변수다. UI에 고정 원화/달러 금액은 없다. 웹 카피만 「매월 사용할 수 있는 더빙 시간」「30분 크레딧 팩」이다.

  • Voice Box 없음: 추출 시 목소리 선택 오류. 설정 화면은 복제/라이브러리 안내.
  • 라이브러리 필터 무결과: 「조건에 맞는 목소리가 없습니다」.
  • 네이티브 Offering 비어 있음: RevenueCat Offering에 패키지를 연결하라는 안내.
  • 프로젝트 id 없음(정적 셸을 id 없이 연 경우): 「프로젝트 ID가 없습니다」.

19.3 동시성

프로젝트당 queued/running 잡은 하나. 두 번째 enqueue는 409. 워커 동시성은 인스턴스당 기본 1(SAD-001). UI는 2초 폴링. 일괄 생성의 서버 잡 대기는 최대 45분.

19.4 잡 취소와 환불

queued/running을 취소하면 finish_job_with_refund. charged_minutes가 있으면 같은 분을 reason=refund로 되돌린다. 이미 끝난 잡은 그대로 둔다. 하트비트 타임아웃(기본 3600초) 실패도 동일 환불 경로다. 추출(0원) 취소는 원장 변화가 없다.
