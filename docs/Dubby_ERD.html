이 문서는 Dubby Postgres/Supabase의 논리 ERD와 엔터티 카탈로그다. 스키마·파이프라인 서술은 DPD-001, 런타임 경계는 SAD-001, 제품 기능은 FRS-001, 프롬프트는 AIP-001을 따른다. 마이그레이션에 없는 테이블은 만들지 않았다.

Dubby 엔터티 관계도DUBBY-ERD-001

1. 문서 개요

1.1 목적

이 문서는 Dubby 3.0.12의 실제 Postgres 테이블과 그들 사이의 관계를 한 장의 논리 ERD로 고정한다. 다음 엔지니어가 추측 테이블이나 일반 webhooks 원장을 만들지 않도록, supabase/migrations/ 17개 파일과 DPD-001을 교차검증한 결과만 그린다.

1.2 범위

  • 포함: public 테이블 14개, 외부 엔터티 auth.users, PK/FK/유니크 인덱스가 정의하는 카디널리티, 논리 참조(FK 없음), API 미사용 waitlist.
  • 제외: 함수·트리거·RPC 본문, R2 객체 레이아웃, 상태 머신, 프롬프트. 이들은 DPD-001·AIP-001에 있다.
  • 제외: Supabase Auth의 다른 시스템 테이블(auth.identities, auth.sessions 등). Dubby 마이그레이션이 FK로 가리키는 Auth 엔터티는 auth.users뿐이다.
  • 사실의 기준: 마이그레이션 최종 적용 형상. 코드에만 있는 필드는 사이드카로 명시하고 박스에 넣지 않는다.

1.4 표기

PK 기본키 (남색) FK 외래키 (파랑) UQ 유니크/부분 유니크 미사용·외부 회색 / 점선 테두리 실선 = 실제 FK 점선 = 논리적 참조, FK 없음

카디널리티는 1:1, 1:N만 사용한다. N:M 조인 테이블은 마이그레이션에 없다. 컬럼이 UUID/text여도 REFERENCES가 없으면 “논리적 참조, FK 없음”으로 표시한다.

2. 논리 ERD

인쇄 시 JavaScript 없이 보이도록 인라인 SVG다. 유지보수는 docs/Dubby_ERD.mmd를 수정한다. 그룹: Identity, Project/media, Jobs, Credits, Voices, Billing events, Ops, Unused.

읽기 순서 auth.users → profiles(1:1)가 허브다. 프로젝트·원장·빌링·로그는 profiles(또는 동일 UUID의 auth.users)로 모인다. user_voices.owner_id만 auth.users를 직접 참조한다. stripe_events·revenuecat_events·waitlist는 사용자 FK가 없다.

4. 엔터티 카탈로그

5.2 마이그레이션에서 생략한 것

  • public 테이블: 없음. CREATE TABLE은 위 14개 전부다.
  • auth 스키마의 identities/sessions/refresh_tokens 등: Dubby FK가 없어 생략. auth.users만 외부 엔터티로 표시.
  • 함수·트리거·RPC: 엔터티가 아님. DPD-001 3.9.
  • R2 키와 매니페스트 필드: 테이블이 아님. 4.16.
검증 17개 마이그레이션에서 create table을 다시 세면 public 14 + (참조만) auth.users. 가상 webhooks 테이블, 세그먼트 status, dubbed_audio_url 컬럼은 없다.
