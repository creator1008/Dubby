이 문서는 Dubby의 스키마, 잡 큐, 크레딧 원장, R2 키, 미디어 파이프라인 단계를 정의한다. 런타임 경계는 SAD-001, 제품 기능은 FRS-001, 프롬프트 전문은 후속 문서에서 다룬다.

Dubby 데이터베이스/파이프라인 설계서DUBBY-DPD-001

1. 문서 개요

1.1 목적

이 문서는 Dubby 3.0.12의 데이터 저장과 워커 파이프라인을 인수인계 기준으로 고정한다. 어떤 테이블이 실제로 존재하는지, 잡이 어떻게 claim·heartbeat·timeout 되는지, transcribe/dub/lipsync가 어떤 단계와 진행 코드를 쓰는지, R2 객체가 DB 어느 컬럼을 가리키는지를 코드와 SQL 마이그레이션에 근거해 기술한다.

1.2 범위

  • 포함: Repository 백엔드, supabase/migrations/ 스키마, 상태 문자열, jobs 큐, 크레딧 원장 행·불변식, R2 키 레이아웃, transcribe/dub/lipsync 단계, 스크래치·재시도·취소, 3.0.12 데이터 함의, 마이그레이션 적용 방법.
  • 제외: Caddy/CORS/터널, Stripe Checkout 화면, 크레딧 요금 UX, STT·번역·TTS 프롬프트 전문. 이들은 SAD-001, FRS-001, 후속 「AI 에이전트 및 프롬프트 명세서」에서 다룬다.
  • 사실의 기준: 저장소 현재 코드(제품 3.0.12, PIPELINE_VERSION = "3.0"). 마이그레이션에 없는 테이블·컬럼은 만들지 않고, 코드에만 있는 필드는 사이드카로 명시한다.

2. 데이터 접근 경로

API와 워커는 저장소에 직접 SQL을 흩뿌리지 않고 create_repository(settings)가 고른 Repository만 사용한다. 백엔드는 Settings.db_backend로 갈린다. 기본값은 postgres이다.

[FastAPI / worker.runner]
        |
        v
create_repository(settings)
        |
        +-- db_backend == "postgres"        --> PostgresRepository (asyncpg)
        |                                      DATABASE_URL, session-mode pooler
        |
        +-- db_backend == "supabase_rest"   --> SupabaseRestRepository (httpx)
                                               SUPABASE_URL + SERVICE_ROLE_KEY
                                               PostgREST + SECURITY DEFINER RPC

2.1 postgres (권장)

api/app/db/postgres.py. Lightsail에서 Supabase connection pooler URI(session mode)로 붙는다. asyncpg.create_pool 파라미터는 config.py에서 온다.

설정기본값역할
db_backendpostgres백엔드 선택
database_url(빈 문자열)production + postgres면 필수
db_pool_min_size1풀 하한
db_pool_max_size5풀 상한
command_timeout30초 (코드 상수)풀 생성 시 고정

기동 시 information_schema.columns로 projects 실존 컬럼을 읽어 SELECT 목록을 줄인다. 아직 적용되지 않은 마이그레이션 컬럼이 있어도 list_projects가 500을 내지 않는다. 빠진 컬럼은 로그 경고만 남긴다.

2.2 supabase_rest

api/app/db/supabase_rest.py. 직접 DB 포트가 없을 때 PostgREST + service-role 키로 동일 인터페이스를 구현한다. 원자 작업은 SQL RPC에 맡긴다.

작업RPC / 경로
잔액credit_balance(p_user_id)
enqueue + 차감enqueue_job_with_credit
claimclaim_next_job() — FOR UPDATE SKIP LOCKED
세그먼트 일괄 교체replace_segments(p_project_id, jsonb)
세그먼트 편집update_segment_texts
종료+환불finish_job_with_refund
stale failfail_stale_jobs(p_timeout_seconds)
Stripe / RevenueCatprocess_stripe_event / process_revenuecat_event

클라이언트 역할(anon, authenticated, PUBLIC)에는 위 RPC EXECUTE가 revoke되어 있다. dub_voice_ids 컬럼이 아직 없으면 REST 백엔드는 R2 사이드카 dub_voice_ids.json으로 보완한다.

2.3 소유권 규칙

base.py: 사용자 대면 메서드는 모두 owner_id를 받고 그 범위로 쿼리해야 한다. API는 privileged credential로 붙으므로 RLS만으로 소유권을 맡기지 않는다. 워커 메서드(claim_next_job, get_project_for_worker, replace_segments 등)는 owner 스코프가 없다.

5.2 잡 status

queued --claim_next_job--> running --finish_job--> completed
                              |                      failed     (error 설정, 환불 가능)
                              +-------------------> cancelled  (사용자 또는 이미 비-running)

사용자 취소: POST /v1/jobs/{id}/cancel → finish_job(..., status="cancelled", error="cancelled by user"). 워커는 다음 checkpoint에서 JobCancelled를 올리고 status를 덮어쓰지 않는다.

5.3 세그먼트

세그먼트 행에 status 컬럼은 없다. 프로젝트 status와 잡이 수명을 나타낸다. transcribe는 전량 교체. 편집은 target_text, source_text, end_ms, speak_speed. source_end_ms·emotion은 R2.

6. Job 모델

6.1 kind

API JobKind와 DB CHECK: transcribe | dub | lipsync. 핸들러 맵 PIPELINE_HANDLERS와 같다. transcribe는 크레딧 0. dub/lipsync는 ceil(duration_seconds/60 * multiplier)를 선차감한다. lipsync는 lipsync_provider != disabled이고 output_key가 있어야 한다.

6.2 claim / poll

python -m app.worker.runner. 루프는 세마포어를 잡고 claim_next_job을 호출한다. 없으면 worker_poll_interval_seconds(기본 3.0) 대기. claim SQL:

UPDATE jobs SET status='running', started_at=now(), heartbeat_at=now()
 WHERE id = (
   SELECT id FROM jobs WHERE status='queued'
   ORDER BY created_at
   FOR UPDATE SKIP LOCKED
   LIMIT 1
 )

worker_concurrency 기본 1, 상한 8. 주석: Demucs 메모리 때문에 소형 Lightsail에서는 1.

9.1.1 assign-by-idx (3.0.12)

gemini_client.translate_batch는 각 항목에 idx를 넣고, 모델이 translations[{idx,text}]를 반환해야 한다. parse_translation_content(openai_client)는 기대 idx가 모두 있어야 하며, 없으면 TRANSLATION_FAILED(retryable). 위치 배열로 빈 칸을 메우지 않는다.

1차 결과를 idxs_needing_retranslate(translation_align.py)가 검사한다. 대상 스크립트 없음, 긴 원문의 짧은 스텁, 짧은 원문의 장문, 슬롯 대비 과장문이면 그 idx만 재번역한다. 서버 워커 경로는 이 재시도 후 postprocess한다.

로컬 스텝(local_step12.py)은 파서가 더 관대하다. 전부 어긋난 1-based/상대 인덱스일 때만 위치 재매핑한다. 부분 매칭 구멍에 이웃 문장을 넣지 않는다. 주석: 그렇게 하면 source/target 쌍이 섞인다.

9.1.2 꼬리 재청취

_fill_uncovered_asr_tail: 첫 STT가 클립 끝 전에 멈추면 후반 타임스탬프가 비고, 번역이 있어도 더빙 때 원음이 남는다.

  • duration_ms < 20000 또는 covered_end ≥ 85%이면 skip.
  • tail_start = max(0, covered_end − 800). 남은 길이가 4초 미만이면 skip.
  • trim → transcribe(asr_tail) → 오프셋 보정 → 기존 청크와 dedupe.
  • quality_warnings: asr_tail_uncovered:{end}/{dur}, asr_tail_failed, asr_tail_empty, asr_tail_appended:{n}.

10. 스크래치·정리·재시도·취소

10.1 스크래치

_make_scratch: 부모는 scratch_dir 또는 시스템 temp. 디렉터리명 dubby-job-{job_id}-. 파일 예: source.bin, asr_audio.mp3, asr_tail.mp3, audio.wav, stems/, clips/seg_{idx}.*, speech_removed_bed.wav, mixed.wav, subtitles.ass, output.mp4, lipsync.mp4.

_cleanup_scratch: rmtree를 최대 2회(0.5초 간격). Windows 잠금 대비. 그래도 남으면 warning. 모든 핸들러 finally에서 호출.

10.2 재시도

_with_retries: pipeline_step_retries + 1회(기본 3). PipelineError.retryable만. 백오프 pipeline_retry_backoff_seconds * attempt(2s, 4s, …). 재시도 사이 check_cancelled. 네트워크/R2/일부 AI 단계가 retryable. 검증 오류(너무 김, 컨테이너, no_segments 등)는 한 번만.

10.3 취소 체크포인트

ctx.report와 ctx.heartbeat가 get_job_status를 본다. running이 아니면 JobCancelled. 러너는 이 예외에서 finish_job을 호출하지 않는다. SIGTERM/SIGINT는 신규 claim을 멈추고 진행 중 잡은 끝낸다.

11. 3.0.12 데이터 함의 — 재추출이 필요한 이유

VERSION.md: 3.0.12는 잘못 할당된 캡션을 재번역하고, 덮이지 않은 오디오 꼬리를 다시 들어 긴 클립이 원어로 남는 것을 줄인다. 이는 UX 문구가 아니라 이미 저장된 행 문제다.

11.1 잘못된 세그먼트 할당

세그먼트 진실은 segments.target_text의 idx 대응이다. 구버전은 모델이 문서 앞부분이나 다른 장면을 한 idx에 넣거나, 짧은 줄에 장문을 붙일 수 있었다. 그 행은 편집기에 그대로 남고, 더빙은 그 텍스트를 읽는다.

3.0.12 워커는 새 transcribe 잡에서만 재번역 휴리스틱을 돌린다. 기존 행을 훑는 마이그레이션 잡이나 UPDATE 패치는 없다. 고치는 방법은 transcribe를 다시 돌려 replace_segments(DELETE+INSERT)하는 것이다. 편집기에서 한 줄씩 고칠 수는 있으나, 후반부 통째 어긋남은 수작업으로 복구하기 어렵다.

11.2 후반 타임스탬프 부재

첫 Gemini 패스가 covered_end에서 멈추면 그 이후 청크가 DB에 없다. 번역 문자열이 문서 컨텍스트에 있어도 세그먼트 행이 없으면 더빙 speakable 구간이 없고, 후반은 원음/뮤트 베드가 된다. speech_ranges.json도 같은 패스에서 잘리면 음량·voice removal이 후반을 놓친다.

꼬리 재청취는 실행 중 transcribe에만 적용된다. 이미 ready_for_edit인 프로젝트의 segments·R2 메타는 자동 수리되지 않는다. 재추출이 필요한 이유:

  • 세그먼트는 전량 교체 모델이다. 부분 append API가 없다.
  • source_end_ms는 DB에 없어 매니페스트가 비면 ASR 끝을 복원할 수 없다.
  • dub은 있는 행의 start_ms/end_ms만 본다. 없는 분을 만들어 주지 않는다.

  • 존재하지 않는 테이블(예: generic webhooks, segment_status, credit_balances)은 설계에 넣지 않았다.
